# Klikintappaja — project context

A Manifest V3 Chrome extension that replaces clickbait headlines on Finnish news
sites (**Ilta-Sanomat** / `is.fi`, **Iltalehti**, and cross-linked **Kauppalehti**
teasers) with concise, factual headlines generated by an AI model — using the
user's **own** API key. Name: a play on *klikinsäästäjä* (click *saver*) →
*klikintappaja* (click *killer*). Fully client-side: no backend, no analytics;
the only data leaving the browser is article text sent to the user's chosen AI
provider.

Prototyped inside a Python project called `uutis` (news clustering), then split
into this standalone repo. The anti-clickbait prompt and the per-site article
extractors were **ported from `uutis`** (`src/uutis/prompts.py`,
`src/uutis/crawler/sources/fi.py`).

**Chrome Web Store:** extension ID `jcdabpknfbcbcdbipfclhknoglhgecjl` (submitted
for review; first upload was manual).

## Layout

- `extension/` — the loadable/zippable extension:
  - `manifest.json`, `content.js`, `extractors.js`, `articleid.js`, `prompts.js`,
    `background.js`, `popup.html`/`popup.js`, `icons/` (16/48/128 skull),
    `README.md`, `PRIVACY.md`, `LICENSE`.
- `store/` — Web Store listing assets (icon 128/512, 1280×800 before/after
  screenshot, 440×280 + 1400×560 promo tiles).
- `build.ps1` — zips the **contents** of `extension/` → `klikintappaja-extension.zip`
  (so `manifest.json` sits at the archive root).
- `.github/workflows/build.yml` — validate + build on push/PR.
- `.github/workflows/release.yml` — on `v*` tag: validate, assert tag ==
  manifest version, build, GitHub Release, optional Web Store publish.
- `PUBLISHING.md` — release + Web Store publishing guide and repo settings.
- `LICENSE` — MIT, © 2026 Kimmo Parviainen-Jalanko. An **identical copy** lives at
  `extension/LICENSE` so the shipped zip carries it; keep the two in sync.

## Architecture / flow

1. `content.js` runs on IS/IL front pages. Headlines are detected as `h1–h6`
   elements or article-link `<a>`. Article-URL patterns: `/art-<id>.html` (IS),
   `/a/<uuid>` (IL/KL). Lazy via IntersectionObserver; MutationObserver handles
   infinite scroll; `data-klikintappaja-state` marks pending/done/skip.
2. A **progress marker** span is appended to each in-play headline — its glyph is
   a CSS `::after` (spinning 💀 while working → subtle ✨ when done → removed on
   skip/fail). Because the glyph is a pseudo-element, it never affects
   `textContent`.
3. Article HTML is fetched **via the service worker** (`background.js`
   `fetchArticle` message), because MV3 content scripts can't fetch cross-origin;
   the SW can, for hosts in `host_permissions`. The content script parses it with
   `DOMParser` and extracts the body with `extractors.js` (site-specific, generic
   fallback), keyed on the **article's** hostname.
4. `background.js` has a **provider registry** (`PROVIDERS`): Gemini (default
   `gemini-2.5-flash-lite`), Anthropic (`claude-haiku-4-5`), OpenAI
   (`gpt-4o-mini`). It sends the ported prompt + article body, sanitizes the
   result, and caches it in `chrome.storage.local` for 24h keyed by **article ID**
   (see 6). A future hosted/shared-API provider (no user key) would be one more
   registry entry.
   An entry is valid only while `sha` (SHA-256 of the extracted body), `provider`
   and `model` all still match — so a **developing story that gets rewritten
   regenerates its headline** on the next view (see 7).
5. Replacement rewrites the headline element's text nodes in place (longest node
   gets the text, others blanked) to preserve site markup/styling. The original
   clickbait stays in a `title` tooltip.
6. `articleid.js` derives the **article identity** from the URL path —
   `is:<digits>` from `/art-<id>.html`, `a:<uuid>` from `/a/<uuid>` (IL/KL share
   the Alma CMS UUID) — falling back to `u5:<uuid>`, a UUIDv5 of the normalized
   URL in the RFC 9562 URL namespace (`6ba7b811-…`). It keys both the SW cache
   and the content script's per-page dedupe map, so one article teased through
   several links is fetched and rewritten once. Loaded in both contexts, so it is
   a classic IIFE on `globalThis.KlikintappajaIds` (like `extractors.js`),
   `import`ed for its side effect by the module SW.
7. **Paywalls.** `fetchArticle` uses `credentials: 'include'` **on purpose** — it
   is what lets a logged-in IS Extra / Iltalehti Plus subscriber get real article
   text (and a real headline). `detectPaywall(doc, host, body)` returns
   `{ premium, locked }`: `premium` is the tier flag from the article itself
   (`is-extra` | `il-plus`), `locked` additionally requires the body to be under
   `READABLE_MIN_CHARS` (1000) — because the tier flag describes the *article*,
   not the reader, so a subscriber's copy carries it too. A locked article is
   never sent to the LLM. The popup's `paywallMode` (`off` | `dim` | `hide`,
   default `dim`) decides the treatment: `dim` grays the teaser and turns the
   marker 💀 → 🫰, `hide` sets `display:none`. `teaserUnit()` picks what to
   gray/hide by walking up only while the ancestor still covers exactly **one**
   distinct article, so a ticker or card grid can never be swallowed.
8. **Cache validity is content-based, never transport-based.** `contentHash()`
   (SHA-256 of the whitespace-collapsed extracted body, 64 bits hex) decides
   whether a cached headline still applies. This is exact rather than heuristic:
   the headline is a pure function of the prompt inputs, and the body is the only
   page content the model sees. `mod` (the article's `dateModified`, via
   `extractModifiedAt`) and `original` (the teaser it was generated from) are
   stored as **hints only** — see the invariants for why neither may become a
   validator.

## Invariants — do NOT regress these

- Progress-marker glyphs are CSS `::after`, **not** text — keeps
  `textContent === original` so detection/replacement stay correct.
- Compare headline text via `collapse(el.textContent)`, never by re-joining text
  nodes (whitespace-node / spacing bugs).
- Cross-origin article fetches **must** go through the service worker; never fetch
  cross-origin from the content script.
- API keys are stored **per provider** under `keys[provider]`, with a legacy
  fallback to a flat `apiKey`.
- The content script's dedupe map must resolve the article ID **synchronously**
  (`articleIdFromUrl`, before any `await`) — awaiting first reopens a
  check-then-set race and duplicate articles get fetched twice. Only the SW,
  which has no such race, uses the async `articleKey` with its UUIDv5 fallback.
- Cache keys are tagged (`is:` / `a:` / `u5:`) so a hashed fallback key can never
  collide with a real Alma UUID. `pruneCache()` treats any `cache:` key
  containing `://` as a pre-ID leftover, and any entry whose `v` is not
  `CACHE_VERSION` as an old shape, and deletes both.
- **Paywall detection must be scoped to the page's own article**, never a
  page-wide string search. Measured trap (2026-08-06): an is.fi page embeds
  metadata for the IS Extra articles it promotes in sidebars, so searching all
  inline scripts for `"paywallStatus":"paid"` flagged *free* articles as
  paywalled. IS is read from the JSON-LD entity whose `@type` ends in `Article`
  (`isAccessibleForFree === false`); IL, which publishes no such field and has no
  single state container, is read from the article element's own Plus classes
  (`.plus-article`, `.article-plus`, `.plus-lead`, `.plus-title`). Both fail
  **open** — undetected means treated as an ordinary article, never wrongly
  hidden.
- **Do not use `ETag`/`Last-Modified` to decide whether to regenerate.** Measured
  against live articles (2026-08-06): `iltalehti.fi` sends no validator at all,
  and `is.fi` rotated its ETag through 3 values in 2.5 min — flipping A→B→A
  inside 52 s — on an article whose extracted body, `<h1>` and `dateModified`
  never changed (`Cache-Control: max-age=9`, multiple CloudFront origin renders
  differing only in ad/"most read" blocks). The churn concentrates on hot
  articles, i.e. exactly where a false "changed" costs the most.
- `mod`/`dateModified` must stay a hint, not a validator: an edit that leaves the
  extracted body identical cannot change the model's output (and the body is
  capped at `MAX_BODY_CHARS`), so triggering on it only buys duplicate LLM calls
  that return the same text.
- `original` (the teaser headline) must stay out of the validity check too, even
  though it is a prompt input: one article is often teased twice on a page with
  different wording, and folding it in would make those placements invalidate
  each other's entry on every single page load.
- **Not remote code**, and keep it that way: fetched HTML is parsed but never
  executed; API responses are inserted only as DOM **text nodes**. No `innerHTML`
  from fetched content, no external `<script>`/CDN, no `eval`.
- Finnish strings and store text must keep correct diacritics (*Jälkeen*,
  *tekoälyn*, etc.).

## Dev workflow

- Validate: `node --check extension/*.js` and `JSON.parse` the manifest.
- Build / test locally: `pwsh ./build.ps1`, then load `extension/` unpacked at
  `chrome://extensions` (Developer mode).
- Release: bump `extension/manifest.json` version → `git tag vX.Y.Z && git push
  --tags`. CI builds, creates the GitHub Release, and (if configured) publishes
  to the Web Store. The tag must match the manifest version or the release job
  fails by design.
- Web Store auto-publish is opt-in via repo variable `PUBLISH_TO_CWS=true` +
  secrets `CWS_EXTENSION_ID`/`CWS_CLIENT_ID`/`CWS_CLIENT_SECRET`/`CWS_REFRESH_TOKEN`.
  See `PUBLISHING.md` for the exact repo settings.

## Environment

- Windows + PowerShell. No package manager / SDKs — the extension calls provider
  REST APIs directly from the service worker (Anthropic: `POST /v1/messages`,
  headers `x-api-key` + `anthropic-version: 2023-06-01` +
  `anthropic-dangerous-direct-browser-access: true`).
- All executable code ships in the package; there is no build step beyond zipping.
